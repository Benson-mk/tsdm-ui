# Appearance implementation — issue #18

Canonical specification: [#18](https://github.com/Benson-mk/tsdm-ui/issues/18), parent #15 and the accepted #6 Text size / #7 Reka follow-ups. Base: `6ccaee92c8b0016433e2d9e774d1dfd0b1ccf328`. This document records the failure-first plan and actual choices; the final evidence audit identifies the verified development scope.

## Confirmed boundary and failure inventory

The human confirmed complete application journeys through layout → workspace → public forum client → browser host, replacing only external HTTP. Native fixture documents can establish real storage conditions. Each run retains the existing receipt, report, source identities, request ledger and inspectable screenshots. No unit-test layer is added.

Reachable failures, enumerated before feature code:

1. Settings lacks an accessible name/description, escapes the ShadowRoot, leaks keyboard focus, or loses its invoker on Escape/close.
2. Range limits/steps, Home/End, current percentage, derived spacing or reset disagree; input saves only at pointer release, or crossing 90%/100% moves the held slider.
3. Missing/invalid/off-step/out-of-range preferences flash an incorrect appearance; storage denial/quota discards the live preference or falsely promises persistence; theme/language fail reload.
4. Nested text scales twice, a fixed-size role does not scale, Compact reduces fonts again, font weights/line multipliers change, browser font preferences fail to compose, or browser zoom changes the derived spacing.
5. Compact leaves default navigation/header/panel/board/list/post whitespace, violates exact row/post gaps, retains a fixed row minimum, shrinks targets/inputs, or changes pane/icon/media/border geometry.
6. Theme has an incomplete foreground/background pair, Mono leaks colored UI, media is recolored, focus loses contrast, reduced motion animates, translated/long labels clip, or Settings cannot scroll at enlarged size.
7. Appearance remounts content, closes disclosures, resets selection/range focus, changes history or performs a forum read; reflow loses the visible reading block despite available scroll bounds.
8. Width transitions lose the results/reader/secondary context or expose a previous section's content. The destination rail and medium/narrow navigation must stay available, including matching overviews for later workflows without performing those workflows.
9. Preference persistence creates a second writing/navigation owner or puts private snapshots in durable preferences/history. Later editor/IME behavior is unqualified until its ticket exists.

Named E2E slices are written before their corresponding implementation: `J5.appearance-keyboard`, `J5.appearance-persistence-*`, `J5.appearance-pointer`, `J5.appearance-roles`, `J5.appearance-context`, `J2.section-overviews`, and `J5.appearance-covering-*`. Installed macOS Edge → Chrome checks remain separate from synthetic qualification. Stable/browser/manager and Windows release obligations remain in force.

## Approach and feasibility

Reuse the current Vue layout, navigation snapshots, one page-session recovery owner and selectively imported Reka Dialog. Add workspace-owned typed preferences through a browser preference host; durable UI preferences contain only theme, language and percentage. Resize the existing mounted layout with shared typography/palette/spacing variables inherited by its sibling portal. Keep the native range and native choices. Preserve visible content blocks around preference reflow. Expose later section overviews without inventing search/saved/notices/draft operations.

Production geometry retains the measured 1280px desktop and 960px narrow transitions. A 192-combination covering set exercises 375, 559, 560, 767, 768, 959, 960, 1279, 1280, 1400, 1440 and 1920px at 70/90/100/150% in each theme, rotating all three languages. It measures visible secondary/picker/results behavior, stable grid tracks, complete long Latin/CJK titles, local overflow, useful reader dimensions and contrast on regular, header, code and quote surfaces. These are production measurements, independent of the prototype's counts. Native Edge currently exposes a 16px root and 12px body; role typography references the root. Editor and IME qualification belongs to the future writing implementation.

## Trade-offs

1. **One origin-local durable preference record** stores only schema/theme/percentage/language through a browser host, with exact write/readback acknowledgement. This needs no new manager grant and keeps UI preferences outside private recovery, but the forum origin can access them, writes consume synchronous origin quota, and simultaneous tabs use their last saved values rather than live synchronization. Refusal retains current-page state with an explanation. No writing or navigation snapshots enter this store.
2. **A synchronous preference load before revealing the host** prevents a wrong-theme/size flash and avoids an asynchronous preference service. Local storage work occurs on startup and each actual input; malformed fields independently use their baseline instead of attempting migration. The record is deliberately small.
3. **Root-relative explicit type roles with one inherited multiplier** compose with browser font defaults and normal zoom across both the workspace and sibling portal. They depend on the document root's font baseline; measured native root16px retains existing role sizes. Pane tracks, controls' target floors, media, borders and radii remain independent, so enlarged text wraps instead of enlarging every dimension.
4. **A fixed Settings inset and full-width native range** keep the track stable across 90/100 while its text changes. The modal therefore retains 32px padding even in Compact and scrolls at enlarged sizes; its surrounding whitespace is intentionally less compact than browsing surfaces. Reka Dialog supplies the selected overlay lifecycle, while native theme radios and language/section selectors retain platform behavior. This bounds the selected primitive inventory; other primitives need their own qualification when introduced.
5. **Visible-block capture around in-place reflow** preserves a paragraph/code/table/disclosure or result/card node with synchronous geometry reads and a next-tick scroll adjustment. The layout remembers pane-relative anchors on scroll and result changes for viewport resize, retaining hidden-pane anchors until they return. This avoids refetching or remounting content, but costs layout work during live input and scrolling and allows paragraph rewrapping, scroll-bound clamping and one-pixel scroll rounding. An initial article-level anchor was rejected by the stronger paragraph expectation before correction. Native browser overflow anchoring alone did not preserve the resize paragraph in a failure-first experiment; the existing explicit policy handles both preferences and viewport reflow.
6. **Typed in-repository translations and an exact application-description map** avoid another runtime dependency and leave returned forum content untouched. Maintainers must add new labels/descriptions deliberately; unrecognized descriptions retain their original text rather than being guessed or mistranslated. Forum-authored titles, criteria labels and bodies retain their source language.
7. **Optional section metadata in the existing navigation entry** makes matching overviews reloadable with safe URLs and passive Back/Forward, without adding a second history/storage owner or changing the recovery schema. Old entries mean Boards. Older applications cannot interpret later section overviews and can report their null result unavailable. Search, Saved, Notices and Drafts expose honest overviews/native continuation here; their actual workflows remain their own tickets. Entering these overviews performs no forum request.
8. **Retain measured pixel pane transitions and one fixed 128px destination rail** while changing typography and spacing: the 192 production combinations establish the current usable thresholds without a viewport-dependent parser or second layout. Screenshot inspection and the failure-first rail-label journey exposed fragmented English words at150%. The rail takes40px more than the previous88px baseline from the flexible reader, stays128px at every percentage and preserves complete words without shrinking type. Large text has less simultaneous reading room; narrow screens preserve one pane and use native destination selection. Future writing views must repeat their own width/IME checks and use the shared workspace guards when integrated.
9. **Bounded development qualification in macOS Edge then Chrome** follows the selected BETA schedule and keeps raw authenticated captures private. Synthetic failures, exact candidate identities and installed outcomes remain separate; it does not qualify Windows, stable manager/browser combinations, a screen reader or the later editor. These remain the existing release/future-ticket duties rather than silently reduced scope.

The inherited nine-step range, automatic Compact threshold, immediate autosave, four palettes, target minima, one production layout and conditional page-session recovery are accepted product decisions already recorded in #6/#7/#8/#15 and the parent ledger. They are not counted again as new choices.
