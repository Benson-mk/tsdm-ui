# Public forum-client 0.5.0 migration

Issue #21 advances the portable `@tsdm/forum-client` contract from 0.4.0 to **0.5.0**. The application/userscript stays **0.4.0**. These are independently named artifacts; `dist/build-manifest.json` records `version` for the userscript and `forumClientVersion` for the library. Consumers must pin the exact library artifact/version rather than infer it from the application display version.

`PreparedWriting.action` now permits `new-thread`, `reply` and `quick-quote`. An exhaustive switch or a variable accepting only `"new-thread"` must account for the two additional actions. `prepareNewThread` continues returning the common preparation-result type, so consumers must narrow the discriminant before relying on an action-specific literal. The required public `ForumClient` interface also adds `prepareReply` and `findMention`; structural implementations must provide those methods. Existing ordinary-publication calls retain their meanings, including immutable submitted revisions, account guards and independent stored-result verification.

Replies use the existing publication/attempt/result contracts with explicit reply-target metadata. One Quick Quote retains one addressed post. Selected-person identities are explicit metadata, and literal at-text is not itself proof of resolved identity or notification delivery. Complete existing-post comparisons retain full before and observed source; unfamiliar source transformations remain uncertain.

The completed Standards review identified the unchanged 0.4.0 library version as a bounded P2 defect against ADR 0001. BDFL validation confirmed source incompatibility while finding no published release/tag or established separately deployed 0.4.0 consumer. The correction therefore advances the local artifact and documents the required migration; it does not introduce a speculative compatibility framework or claim a production outage. The Spec review had no actionable implementation findings.
