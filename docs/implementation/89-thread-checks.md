## Distinct actual trade-offs

1. A first distant newest observation establishes a baseline; previously unseen old posts are not called arrivals. Thus changes before that baseline cannot be classified. Settings explains this and the initial check explicitly reports the baseline. Later stable identities are counted once, independently of loaded old-history membership.
2. Distant checking retains one bounded newest snapshot and does not merge a disconnected page into continuous reading. Reveal uses the existing guarded source navigation, re-reading the selected actual new post; this preserves navigation/writing guarantees at the cost of an additional deliberate read and possible fresh server changes.
3. A source-confirmed growing last page may cause one additional newest-target read under the same pending/epoch owner. A second moving boundary stops with visible deliberate recovery instead of an unbounded catch-up loop.
4. Reverse presentation follows native source page/post order while the existing range owner stays chronological. The exact observed pinned prefix (#/-1#) remains before replies; check/follow uses the first following positive native floor. Unknown/ambiguous labels keep the first source post as the boundary instead of guessing. This preserves native pinned content but means “top” is the start of the newest reply sequence after that prefix.
5. A compact reserved status/action row and timestamp/boundary metadata keep passive updates from changing reader geometry. They consume stable heading space even with no arrivals; full error details expand only deliberately. Settings is the single automatic-check opt-in surface, removing the duplicate heading control to preserve short-screen reading space. The details information icon retains a name/tooltip; visible successful-check text uses day/time without seconds/year, with the full authoritative timestamp accessible through keyboard focus, screen-reader label and tooltip.

6. A breadcrumb focused during compaction, or reached later by keyboard, remains visible until title expansion or thread change. This temporarily spends heading space to keep focus and pointer targets stable through a gesture; untouched compact breadcrumbs still hide.
7. More returns focus to its existing trigger without scrolling, while outside interactions keep their intended focus. This protects the restored reader anchor; in a short viewport it does not forcibly scroll a clipped heading back into view solely to reveal that trigger.

Existing 120 second cadence, backoff,64 px proven-latest rule and Edge-first testing are inherited constraints.
