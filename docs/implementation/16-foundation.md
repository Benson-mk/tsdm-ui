# Foundation: failure inventory and qualification boundary

Before feature code, the confirmed application boundary is maintained layout → typed workspace → public forum client → browser host. Playwright replaces only external HTTP responses. The separate clean Node consumer imports the packed public library. These are the previously agreed seams; no component or unit runner is introduced.

## Reachable failures recorded before implementation

- A matching thread does not start; a nonmatching page is replaced; duplicate startup creates two workspaces; a startup failure removes emergency native access.
- A populated response loses title, thread/post identity, author, floor or readable text; malformed or unfamiliar markup becomes a false empty success.
- Remote scripts, handlers, CSS, frames, unsafe protocols or fetched controls run; links silently perform actions or image handlers trigger charges.
- Guest is confused with unknown/member merely because a token exists; author identity is mistaken for current member; a stale request overwrites a newer account result.
- Login, permission, missing, verification challenge, invalid response and network failure are collapsed; retry/native recovery loses the target.
- JSON-preferring request receives useful HTML and needlessly repeats a request; malformed JSON is treated as a valid page.
- Reka dialog leaves its ShadowRoot, loses accessible naming, permits focus escape, closes unrecoverably, or fails to return focus.
- Built runtime depends on a CDN; metadata admits unintended origins or automatic updates; CSS does not reach the shadow tree; library accidentally imports Vue/GM/DOM/editor.
- The clean consumer cannot install/import declarations; imports touch browser globals; a populated public result cannot round-trip JSON; package content differs from checked source.
- Receipt/report omits candidate/tool/fixture identity or failures; public output contains private captures or workstation paths.
- Synthetic injection is mislabeled installed manager verification; actual stored script, one enabled entry, matching/nonmatching pages and style/startup have no evidence.

## Initial named expectations

`J2.thread-populated` proves the entire read stack with server request readback and inert rich content. `J1.reka-shadow-dialog` proves keyboard focus containment/return and portal placement in the actual application shadow tree. Negative response, overlap/session, nonmatching/native recovery, JSON/HTML and clean-consumer cases are added before their implementation slices. Screenshots are authored synthetic artifacts, not real member captures.

## Decision ledger

1. Use parse5 to interpret HTML in the shared client: a portable inert tree supports Node consumers, at the cost of parser bundle bytes and explicit traversal/rendering work. No browser DOM enters exported models.
2. Prefer the observed `tsdmapp=json` page representation and consume returned HTML directly: preserves known metadata benefit without duplicate reads, but both response paths need qualification.
3. Start with read-only explicit public client/workspace contracts and one production layout: gives later tickets stable extension points, while deliberately withholding unimplemented operations.
4. Pin Node 24.22.0/npm 11.21.1 and compatible TypeScript 6.0.3: retains supported LTS and lint/checker compatibility, at the cost of deliberate dependency updates rather than latest-major adoption.
5. Bundle the client library independently with its parser: removes consumer peer/runtime UI requirements, at the cost of duplicating parser bytes between separately consumed artifacts.

6. Reconstruct approved content tags and attributes into serializable nodes, then Vue nodes: prevents fetched code/handlers/classes/styles from entering the active document, but unfamiliar formatting and interactive embeds require explicit explanations. Complete rich-thread behavior remains #17's own acceptance work.
7. Restrict the initial host to the observed HTTPS forum origin and reject ambiguous/unknown thread query fields: avoids unintended request semantics, at the cost of explicit native recovery for routes not yet supported.
8. Observe page-JSON uid or a unique native account header outside post content, and reject older overlapping responses: prevents post-author impersonation and stale replacement, but unknown observations remain unknown and ambient browser cookies cannot be made atomic.
9. Use native same-origin Fetch with current browser credentials: fits the accepted account host without granting privileged requests, but observable redirects and live cookie behavior still require installed qualification.
10. Place the styled workspace and the selectively imported Reka dialog in one ShadowRoot: bounds stylesheet and portal interactions, but the shared DOM is not a security boundary and installed keyboard/CSP behavior still needs evidence.
11. Use an explicit native bypass URL and manager recovery command: keeps the intended destination recoverable even when application mounting fails, at the cost of an extra inert query parameter and deliberate re-entry.
12. Qualify Chrome's built artifact with network-edge interception and a separately packed Node consumer: exercises production parsing/rendering and catches declaration packaging defects, but neither proves installed manager storage, browser lifecycle or live forum effects.
13. Add explicit declaration dependencies rather than skip library checking; disable two core JavaScript lint rules only in Vue SFCs because TypeScript and template-aware linting own those checks: retains strict declarations and useful Vue linting, at the cost of small compatibility-specific configuration.
14. Keep generated receipts and captures outside version control until inspected, and use authored fields for public reports: avoids silently publishing private evidence, but candidate/evidence retention must be explicit before worktree cleanup.
15. Scope formatting commands to implementation-owned files: prevents incidental changes to inherited decision records, at the cost of not reformatting every existing Markdown file with this ticket.

16. Include a complete authored fixture/scenario snapshot in each synthetic package: makes its inputs inspectable alongside screenshots and receipts, at the cost of duplicate source bytes. The snapshot is captured from the executed source, and the manifest checks its exact identity.

17. Keep original native body siblings present but inert and hidden from the accessibility tree while the workspace owns the view: avoids exposing duplicate native actions, at the cost of saving/restoring each sibling's previous state and observing newly appended siblings.
18. Replace explicitly hidden native content branches with a native-continuation explanation: prevents inactive success text from becoming a false observed outcome, at the cost of withholding that hidden content. This recognizes `hidden` and inline `display:none`/`visibility:hidden`; the observed `#hb_mask.mask` containing `#hb_env.env` is separately recognized as a native red-packet interaction template and explained without exposing its inactive outcomes. It does not interpret arbitrary external stylesheets or native scripts.
19. Synchronize same-document fragments into the workspace destination and read the current location when invoking manager recovery: preserves the selected post without an additional forum read, at the cost of a fragment listener. Read completion retains the current destination, so a pending refresh cannot reset a newer fragment. Full navigation/history policy remains #17.
20. Retain a separate execution-world application experiment in addition to ordinary script injection: covers one plausible userscript realm difference, at the cost of a Chrome-specific CDP setup. It does not establish Tampermonkey key handling or override the observed installed failure.

21. Deferred adjustment of the observed native word-breaking until its concrete cascade cause was qualified: avoided a speculative style change, at the cost of a second narrow qualification cycle. The subsequently observed universal rule is now covered by the correction below.

22. Handle an uncancelled Escape inside the controlled About dialog before it reaches the native body's known cancellation handler: preserves dialog dismissal and Reka's focus lifecycle without changing native handlers, at the cost of one presentation-level event adapter. Descendant cancellation remains respected; only an Escape actually handled by this dialog stops propagating. Later nested primitives still require their own keyboard qualification.

23. Normalize word-breaking at the application workspace and sibling dialog roots: prevents the observed native universal rule from splitting application words while preserving native styles, at the cost of owning this inherited property in both presentation roots. Existing long-content wrapping rules remain independently applied.

24. Qualify emergency recovery through the accepted startup-independent manager/URL mechanism with the script disabled: verifies the required user outcome without adding internal host mocks, at the cost of leaving the optional automatic catch-path recovery link unexercised. This is not presented as an injected bootstrap exception; the controlling #9 contract explicitly permits disable/native recovery.

The installed candidate showed a dialog that stayed open on Escape even though Close/Enter and focus restoration worked. ### Installed follow-up diagnosis and local outcomes

The exact original installed artifact passed stored-source identity and direct-thread startup checks, but failed Escape dismissal, native background accessibility isolation and current-fragment recovery. The three independently reproducible defects were tested before correction through the existing complete application seam:

- `playwright test --grep native-background` found one native background link when zero was required. Suspending native siblings with `inert` and explicit `aria-hidden` removes duplicate accessible actions while preserving native recovery.
- `playwright test --grep hidden-native-state` showed inactive credited-success text alongside the current exhausted state. Preserving the hidden branch as an explanatory unsupported-content node removes that false effect while keeping adjacent readable content.
- `playwright test --grep current-anchor-recovery` lost `#pid102` from the native continuation href after selecting Post 102. Current-location recovery plus workspace fragment synchronization now retains the exact target without another forum read.

At that stage all three corrected targeted cases passed. Original and separate execution-world Escape cases also passed locally, but neither reproduced the real manager failure; a second installed CUA key path still failed on the original candidate. No speculative dialog fallback was added. Subsequent native-handler evidence and its correction are recorded below; that candidate still required installed requalification. The later final-candidate observations are recorded in the acceptance audit. Historical failing runs and original retained candidate bytes are preserved separately.

A later installed DOM observation identified the CSS-hidden native packet overlay `#hb_mask.mask` with `#hb_env.env` inside it. The additional `J2.native-packet-overlay` authored fixture failed before the structural guard was added (expected no credited-success text, found one), proving the inline-hidden guard alone was insufficient. The parser now explains this known native interaction branch while preserving the visible state and surrounding post. It makes no claim that an operation occurred and implements no packet action.

The original installed page also inherited native `word-break: break-all` in controls/dialog copy. The initial parser/recovery correction retained this limitation pending concrete cascade evidence; the later observed universal rule and bounded correction are recorded below.

Before final candidate freeze, the recovery failure inventory also includes a late read response overwriting a newer same-document fragment. The test must select a fragment during an intercepted pending refresh and verify the final native destination after that read settles.

`J1.anchor-during-read` also failed before correction: the destination included the newly selected fragment while a refresh was pending, then lost it after that older read completed. Read completion now updates result/loading only, retaining the current destination under the existing request-sequence guard.

## Escape host-handler failure inventory (before correction)

Installed diagnostics confirmed `BODY#nv_forum` has `onkeydown="if(event.keyCode==27) return false;"`; Reka's window listener receives Escape with `defaultPrevented: true`. Before correcting this integration, the authored full-application fixture must reproduce the same host body condition and prove the dialog remains open. Reachable failures are: native body cancellation prevents dismissal; a workaround removes native page behavior globally; it bypasses descendant cancellation or closes unrelated overlays; focus restoration is lost; ordinary and isolated-world keyboard behavior regresses. The correction must remain within the selected dialog's presentation boundary and keep the native body attribute unchanged.

The exact observed native body handler made `J1.native-escape-handler` fail with the dialog still visible (`2026-10-17T22-25-57.997Z`), matching the installed symptom. The dialog now handles an uncancelled Escape at its local content boundary and closes via Reka's controlled-open API before the native body can cancel it. The existing native attribute remains unchanged. This corrects a reproduced host interaction; the later final-candidate installed replay is recorded in the acceptance audit.

## Native word-breaking failure inventory (before correction)

The installed cascade now identifies the native universal rule `* { word-break: break-all; }`, which styles the workspace host and is inherited through the shadow boundary. Reachable failures are arbitrary mid-word breaks in application buttons/dialog copy, a reset that misses the sibling dialog portal, and an overbroad reset that changes the native document. The authored complete application case will use that exact rule, check application/control/portal word-breaking, and verify the native body retains its original computed rule.

The native word-break fixture failed before correction with actual control `break-all` instead of expected `normal` (`2026-10-17T22-27-04.059Z`). The workspace and sibling dialog root now explicitly use normal word-breaking. The authored case verifies both roots and checks that the original native body remains `break-all`; it also retains a narrow-screen open-dialog screenshot. No broader typography or layout policy was changed.
