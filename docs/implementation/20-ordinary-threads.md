## Plan and accepted boundaries

Drive the real layout → workspace → public forum client → host, replacing only external HTTP. Observe visible outcomes and independent synthetic server state/effect counts. The separately installed public library is the additional consumer seam already accepted by the human. Named expectations precede their feature code; no unit/component test layer is added. Root owns completed-work Standards/Spec/BDFL review, installed checks, live-write authorization and the eventual commit.

1. Extend portable current-form interpretation to retain private successful controls for an ordinary new-thread command. Prepare a fresh account/board/form-bound publication of one immutable writing revision; expose only serializable token-free review metadata.
2. Persist a pending attempt before any POST and reject duplicate, stale or changed preparations. Preserve later source revisions independently from the submitted revision. Classify explicit validation refusal, reported moderation, independently confirmed stored result and uncertainty without retries.
3. Independently read the public opening-post identity/actor and its current editable complete source/options through fresh GETs. Treat callback/redirect destinations only as candidates. Retain confirmation if later presentation fails.
4. Recover pending attempts as uncertain without sending. Explicit Check result retains the original attempt and can verify a user-supplied candidate thread URL when a lost response contains no identity. An inconclusive check enables a warned deliberate resend with a fresh preparation and attempt, preserving the old unknown.
5. Exercise the failure/session matrix and clean public consumer; retain red/green runs and inspect artifacts. Merge the current integration tip before final checks. Prepare a concrete bounded live case; no live actions occur in this offline work.

## Actual trade-offs

Record each actual distinct choice here as it is implemented. Inherited one-context/page-session and ambient-account limitations remain in #19/#15 and the ADRs.

1. Keep successful controls and tokens in a private client-lifetime preparation map, exposing only the immutable token-free submission and preparation identity. Refresh cannot reuse a secret-bearing form; any new send needs fresh preparation.
2. A lost response with no result identity uses an explicit candidate thread URL for independent result checking. This avoids speculative forum searches or claiming an arbitrary matching old thread as the attempt; the member must supply a candidate when the response provides none.
3. Retain submitted attempts alongside the current writing in the existing page-session record. Later edits and original unknowns stay inspectable, while long-lived writing can reach the same finite recovery quota and must visibly refuse a new send when its pending snapshot cannot be acknowledged.
4. Confirm independently verified stored publication with complete literal source/title/category and persistent options, permitting only the qualified present, enabled empty price actually included in the command → present0 normalization and preserving the immutable submitted blank. A disabled blank is omitted from the command and cannot qualify that normalization; unchanged disabled values still compare literally. Separate only the three named checkbox creation instructions from persistent fields; expose requested state, actual command inclusion and independent unknown/not-requested effects in the portable result. This supports the observed native form without inventing persistent defaults or delivery from missing edit controls/callback feed IDs. Unexplained normalization, missing persistent state and additional action variants still require qualification. The historical9921 all-options-equal rule was overstrict and remains a documented native failure, not a passed run.
5. Recheck the authoritative current form/account immediately before POST, in addition to the explicit review preparation. This adds one GET and a final stale-control refusal; an ambient cookie can still change afterward, so it provides no atomic isolation or rollback guarantee.
6. Interpret a bounded literal native XML callback grammar without execution. Unsupported/malformed envelopes remain uncertain, so additional native response variants need qualification.
7. Preserve native inactive rush-control defaults for ordinary publication while refusing active/nonempty rush settings. Tags is exposed as an ordinary current option; the specialized rush-reply workflow remains outside ordinary-thread scope.
8. Preserve either qualified ordinary submitter literal, `yes` or `true`, rather than normalize the current body value to the action query. Unqualified literals remain refused pending interpretation, bounding support without silently broadening specialized workflows.
9. Stop only bubbling `keyup` events at the workspace host after inner handlers have run. This isolates the observed native document paging without cancelling native control defaults or changing native handlers; document/window capture listeners and other event types remain outside this bounded repair. Per-control hooks would repeat the boundary rule and miss other workspace targets, while replacing the native handler would couple recovery to forum internals.

10. Advance the public pre1 contract to0.4.0 for the stored-publication meaning and typed evidence, while retaining schema2 compatibility with older uncertain attempts and optional evidence only on legacy confirmations. This avoids dropping the original saved attempt; strict validation rejects malformed new evidence, but same-origin recovery/caller input remains trusted only structurally, never cryptographically.
11. Preserve a known prior stored confirmation when a fresh result recheck fails, with a separate current-check failure explanation. This protects established publication identity and avoids offering duplicate-send recovery for unknown effects, at the cost of retaining explicitly historical evidence when current freshness cannot be established. The failed check neither upgrades delivery nor rewrites later writing.

Rejected and corrected testing choice: replacing the native storage setter gave precise failure/interleaving control at the cost of qualifying the actual browser host and reachable user scheduling. That cost violates the agreed HTTP-only substitution seam. The native-quota replacement and removal of the fabricated reentrant-edit case below correct this evidence choice; it is separate from the retained product choices.
