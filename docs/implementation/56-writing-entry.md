## Actual trade-offs

1. Keep the existing internal `quickQuote`/`quick-quote` identifiers and native addressed-target contract while changing the user-facing action in all three languages. This avoids a portable contract/version change, at the cost of different internal and visible vocabulary.
2. Repeat a compact action/account/board/thread/target summary beside the editor and review controls. This uses extra vertical room, but makes each interaction understandable without relying on the global account header. An available review uses the immutable prepared writing; otherwise the summary describes the retained context. No second writing store or submission path is introduced.
3. Group destination, applicable title/category and body before account/form checks and operation controls. This changes keyboard Tab order and puts review farther down the form; it makes the writing being entered coherent while retaining the existing tools/options for the later editor tickets.
4. Keep source-first body focus for fresh entries and restore the retained editor mode/selection on re-entry. New-thread title remains an explicit field rather than receiving automatic title-first focus. This preserves the established source policy and the current shared editor session.
5. Supersede old read preparations through the existing workspace sequence rather than aborting external HTTP. A superseded GET can finish, and a newer edit may start another read; neither its result nor its focus can replace the newer intent. Fresh entry clears older replacement guards, while a deliberately requested replacement retains its guard on refusal so the member can retry explicitly.
6. Restrict the pending-preparation focus check to automatic entry focus. Explicit mode/tool commands retain their existing focus behavior while a retained form is checked. This adds a small internal distinction, avoiding a broad focus prohibition that would leave a deliberately selected visible editor unfocused.
7. Use representative appearance combinations and repeat the affected final paths after each narrow correction. The final runtime has fresh entry/focus/selection/account tests, while the larger unchanged-path regression results retain their earlier runtime identities. This reduces redundant full-suite runs without claiming that historical results qualify changed executable bytes.
8. Use a physical owner CJK interaction followed immediately by independent application readback after automated native probes produced Latin input. This supplies genuine installed CJK evidence, while in-progress composition sequencing remains synthetic and the later physical phase has no continuous HTTP ledger. The earlier bounded automated ledger retains its narrower scope.
