## Trade-offs

- Used one routed built-userscript journey with a strict GET allowlist rather than a new fixture framework or live operations; this proves deterministic integrated behavior without side effects, not native forum semantics. The longer continuous path localizes failures with checkpoints, while smaller existing cases cover refused and delayed results.
- Exercised Saved and Notices on that continuous path, then separately replayed Drafts, Messages, Search and other destination states rather than requiring every branch/product state in one journey. This bounds coupling and runtime; full cross-product coverage is not claimed.
- Measured localized Search after the application entered the target layout instead of changing responsive CSS to pass a transient sample. No promise is made about a single pre-layout frame.
- Used actual Edge and Chrome builds in headless isolated contexts on the same artifact, with deterministic viewport, forced-color, composition-event and pinch coverage. Native zoom and installed focus/host/writing qualification are separate; physical IME and screen-reader speech cannot be inferred from those checks.
- Kept Edge as the default and enabled Chrome only through `TSDM_E2E_CHANNEL` rather than making every existing replay launch both browsers. Browser coverage is explicit in the replay command and receipt, not implicit in the HTTP-boundary mode name.
- Reused the existing toolchain and SHA-256 receipt verifier rather than introducing a new runner or claiming the pinned toolchain was exercised. Receipts record the actual tool versions and exclude personal profile data. `synthetic-network-edge` means the HTTP boundary, not Microsoft Edge.
- Preserved the baseline failures and updated three test interactions to exercise current UI contracts: the non-reply guard, explicit Source mode, and hidden status. The retained cases test the original geometry, composition and timer outcomes without changing those production paths.
