## Native keyboard defect

The Text size range and complete-source caret exposed unintended native page
navigation. Two filtered passive traces retain **24 trusted key-event samples**
(**12 per trace**), with the real inner INPUT or TEXTAREA first in the composed
path while outer listeners see the DIV workspace host. Native
`document.onkeyup` calls `keyPageScroll`, which excludes only ordinary INPUT
and TEXTAREA targets. ShadowRoot retargeting defeats that exclusion.

An ArrowRight from the range initiates native document navigation; an ArrowLeft
from the source caret also initiates navigation instead of preserving the
expected editing context. Request initiator stacks identify the native
handlers. The reproduced cases have zero synthetic stored posts and no live
publication action. Acknowledged source survival does not turn lost focus,
caret position or unintended navigation into a pass. The native-range symptom
was also observed in Chrome; the 24 detailed filtered samples are the two
recorded Edge traces, not 24 independent tests or a claimed pair of full
cross-browser event traces.

The Edge diagnostic temporarily changed text size to 110% and restored 100%
through the ordinary UI. Its disposable tab was closed with interception
active; document-bound observers ended with their navigated documents/tab.
Chrome's temporary preferences/viewport were restored and its diagnostic tab
closed. Original live task contexts remain preserved. Narrow 150% screenshots
supply limited visual observations only; this package claims no responsive or
full keyboard acceptance pass.
