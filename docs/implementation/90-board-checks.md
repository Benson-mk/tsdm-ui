## Implemented behavior and distinct actual trade-offs

1. Checks observe the source-supported first page in the same board/filter/order context. A distant first observation establishes a baseline, so pre-baseline differences and arrivals that never remain on that bounded page cannot be classified. “New” means newly observed stable membership in this list, not proof of thread creation time or a complete forum-wide change feed. Real ordinary/category/creation-order page-two responses explicitly offered matching first-page links.
2. Explicit reveal adopts the deduplicated last successful first-page snapshot in source order through the existing workspace/recovery owner. A later-page reveal names its first-page destination. This avoids another request or guessing insertion positions, while showing the last observed snapshot rather than promising latest server state at click time. The selected reader/writing remain retained even if their row is no longer in that snapshot.
3. Staged observations and membership are transient and reset when the displayed source context changes; revealed rows enter ordinary acknowledged navigation recovery. This isolates contexts without new persistence, at the cost of discarding an unrevealed count on leaving/reloading that context.
4. A small board-specific owner uses the existing one-second layout timer, 120-second cadence, busy guards and capped 2/4/…/30-minute failure delay. Thread/history and board requests exclude one another. Waiting for another visible participant retains the due deadline, while hidden/modal/deliberate work resumes with a fresh interval. This keeps existing domain ownership and avoids a generic polling platform, at the cost of keeping matching timing policy in two focused owners. Settings owns one in-memory opt-in for both contexts; explicit reader/page navigation restores it off, preserving the inherited request policy. Browsing a board beside the same retained reader keeps the opt-in.
5. A compact reserved status/action area keeps passive checks/counts from moving rows. It consumes stable space even with no arrivals. Full error and cooldown details open deliberately through a named information control; the status retains concise failure wording. Visual QA rejected the first excessive reservation and qualified the smaller English/Chinese enlarged layout.
6. Any workspace observation of an unconfirmed account discards staged arrivals, visibly suspends automatic board checking and requires a fresh baseline after a successful deliberate retry; the previously displayed public list remains as retained content with a visible failure. This sacrifices a potentially valid old count rather than offering another account's staged snapshot.

The Edge-first cadence, page-session authority, source semantics, retained reader, writing guard and immutable review are inherited constraints. No portable client file changed; no external-consumer rerun is required for this slice.
