## Implemented behavior

The forum client owns fresh policy and account validation, multipart transfer outcome, fresh pending-list fields, association verification and immediate removal. The workspace retains account-bound rows and local byte selections. The browser host sends the original filename and bytes using XHR, reports transfer progress and handles cancellation. Upload success, source insertion and independently verified saved association are separate states.

New-thread, reply, quote and own-edit share this operation. Existing saved references are exposed without inventing original filenames. Restored selected rows require reselection; interrupted rows remain uncertain. New attachments cannot enter the separate forum-draft lifecycle before issue 27 integrates it. Existing associated draft attachments continue through the baseline preservation path. Resumed drafts explicitly disable selection and server-file removal; the portable operations refuse before preparing an ordinary form for a draft target.

An explicit stored-file check uses the existing download capability to compare filename, byte length and SHA-256 against selection. This discloses normalization independently of source/association confirmation. Remote file removal requires a warning, sends the native effectful GET once and confirms absence with fresh source and attachment-list observations. Removing a source tag or discarding local writing does not delete the server file.

## Trade-offs

The following are the distinct choices introduced by this ticket. Existing fresh-read/account-generation latency and non-atomicity, routine Edge cadence, isolated integration and feature-local localization/fallback decisions remain inherited; they are not counted again.

1. Use the ordinary generic uploader for permitted images and files. This preserves bytes and avoids conversion or a second image-only transport, while server-specific image presentation still requires native qualification.
2. Parse a bounded literal projection of the current native initializer without executing remote JavaScript. Dynamic or ambiguous required policies refuse upload; this is deliberately narrower than a JavaScript interpreter.
3. Accept only qualified zero/absent legacy queue/session-limit settings. Nonzero settings refuse until their counter semantics are qualified, reducing availability instead of guessing a limit.
4. Keep selected file bytes only in memory and retain recovery metadata. Refresh requires reselection, avoiding persistent file-byte storage at the cost of interrupted selection convenience.
5. Keep explicit server deletion separate from local source removal and discard. Immediate deletion is irreversible; uncertain results stay visible and are checked without repeating the delete request.
6. Ignore empty dormant replacement sentinels only in edit-version comparison, while preserving current successful form controls for submission. This permits ordinary native resaves without implementing file replacement.
7. Make stored-byte comparison explicit. Association confirmation does not automatically download files or prove byte identity; an additional user action provides that evidence.
8. Use an Attachment ID label when native source exposes an existing reference without its filename. Existing files remain actionable without claiming an unobserved original name.
9. Block new-upload state from forum draft saves and disable new selection on resumed drafts until the dedicated integration ticket. Existing associated-file preservation remains supported; new draft attachment authoring remains visibly unavailable.
10. Keep acknowledged upload rows visible until the writing is discarded or the remote file is explicitly removed. This sacrifices a per-row local forget action to prevent invisible retained submission metadata; unsent/interrupted selections can still be removed locally.
11. Use a minimal structural cancellation contract in the exported library. Native browser AbortSignal satisfies it, and ES-only consumers need no DOM declarations; hosts must implement abort subscription correctly.
12. Permit only one upload transfer at a time in the workspace. This simplifies limit/account/recovery handling at the cost of concurrent upload throughput; files can be queued together.
13. Keep an uncertain upload without an accepted ID as an explicit native-list continuation instead of offering a blind resend. There is no automatic retry, but reconciliation and any new upload require separate deliberate action outside this surface.

14. Advance the portable client from 0.7.0 to 0.8.0 for required attachment methods, keeping the app at 0.4.0. Independent structural consumers must migrate and pin this artifact; runtime installation continues to depend on exact userscript bytes.

15. Reject a local file-read completion after its writing context or account generation changes. The user must reselect files for the current writing, avoiding additional persistent pending-read states and preventing silent retargeting. Same-context typing does not invalidate the selection.

16. Read the complete current native form for upload policy and authorization instead of its smaller JSON projection. This preserves exact declared limits without interpreting a rounded daily allowance, at the cost of a larger response and continued dependence on the qualified literal initializer grammar. It replaces the existing preflight representation; it does not add a second preflight request.

17. Preserve only a qualified native attachment insertion instruction, rather than inferring image references from filename/MIME or accepting arbitrary source normalization. New uploads carry the validated `attach`/`attachimg` kind through recovery. Existing or older recovered rows without that information remain preserved, but insertion directs the user to the native editor; older unassociated uploads also need native continuation when fresh metadata cannot match their missing kind. This costs convenience for those rows and requires the qualified native instruction grammar to stay current, while preventing silent image-tag rewriting and false exact-source confirmation.
