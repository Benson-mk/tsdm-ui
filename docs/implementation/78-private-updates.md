## Distinct trade-offs

1. Private checking/following requires complete observed coverage and no returned outer boundary. This costs availability on partial history, including a seemingly final page without full count coverage. It avoids borrowing public latest proof or treating a native last marker/absent next link as a private guarantee.
2. The separately disclosed private120second policy may mark messages read. It bounds traffic at the cost of discovery delay, full-interval resume, deliberate cooldown recovery and renewed opt-in after cached peer return. The interval is an app policy, not a server promise. Live qualification remains one-page; multipage behavior uses authored fixtures. Shared scheduling/backoff costs are inherited from #71 rather than counted again.
3. Private reload keeps untrusted safe marker metadata while received bodies remain document-only. Recovery costs an explicit authorized read and reconstructs one containing page instead of every former range page. Ordinary live-document returns retain the entire range without that GET. The metadata associates a context; it does not authenticate server provenance.
4. Automatic private checking pauses for visible writing or any original pending/uncertain private attempt, even after choosing another peer. This prioritizes editing/recovery at the cost of delayed discoveries elsewhere. Independent deliberate reading can show arrivals without changing original-attempt authority; an unused review or active preparation/send blocks it.
5. Refresh prefers an explicit returned link for the newest observed page and otherwise rereads its actual returned URL, rejecting a changed current-page identity. A native no-page URL may move as history grows, so safe refresh can require deliberate returned-page loading instead of guessing page arithmetic. This is the private routing cost beyond #71's actual-page strategy.

6. Reading restoration now retains the visible line if a changed heading or viewport makes its old screen coordinate physically unavailable. It first spends available outer scrolling to retain both; otherwise the line moves with the reader. The safe private recovery marker gains two optional geometry numbers, while older markers keep their compatible legacy behavior until a new capture. This policy is activated only for private readers in this slice, preserving the accepted public behavior at the cost of deferring a public visibility audit to #79. This explicit visibility priority replaces a misleading absolute-coordinate-only guarantee.

7. The final private article uses8px end padding and suppresses margins of terminal non-br siblings so the minimum96px reader can expose a complete body text line at strict scroll end. This reduces decorative end spacing, including terminal blocks inside the final article, compared with other messages. Body nodes, parsing and the portable contract remain intact.

Inherited costs are not counted again: the separate private model/client contract and received-content memory (#76), range aliases/no speculative eviction (#70), newest-page snapshots/seen-ID accounting and static heading controls (#71), shared view anchors/media/focus (#69/#71/#76), and the immutable private attempt owner/schema3 (#77). No generic history refactor or second writing/persistence owner was introduced.
