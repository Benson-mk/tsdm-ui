## Distinct actual trade-offs

1. Retaining an exact live range across repeated layout changes prevents wrap-induced drift, but needs geometry/scroll validity and existing history-revision fencing. It remains in-memory and falls back to fresh rendered content when the old observation no longer describes the view.
2. Typography retains each action’s immediately prior screen coordinate while possible; when a larger heading would hide that glyph, visibility takes priority and its prior reader-relative offset is bounded to the real clip. This intentionally permits a screen-coordinate change only in the explicitly tested clipped case.
3. The actual wide-aside transition requires a post-render restoration in addition to browser resize handling because its measured width settles later. Reusing the same range/history owner avoids a second state machine at the cost of coordinating those two render boundaries.
4. The integration matrix uses three entry widths and distributed theme/text/width transitions, with the larger feature matrix covering edge cases. This keeps full-application evidence tractable without a blind Cartesian product; installed browsers and physical-device limits remain explicit.
5. Coverage uses exact case families and a registry rather than duplicating every assertion in60rows. Full case bodies and candidate-scoped receipts remain the authority for individual subclaims.
6. Three independent real-clock file workers reduce elapsed time while sharing machine scheduling resources. Each retains its isolated context, real durations and exact request assertions; failures would remain evidence rather than being excused as timing noise.
7. Corrupt-recovery fixtures install their exact authored browser-storage input at next-document startup to avoid pagehide replacing it. This explicitly controls input delivery timing while preserving production boot/rejection behavior and exact raw/no-effect assertions; it does not test corruption surviving a legitimate subsequent save.
8. After status and safe-edge consumption, bottom writing can be shorter than its previous viewport-based maximum. Its existing inner scrolling carries more controls so the reader keeps its actual visible minimum; wide-aside sizing keeps its existing independent override.
