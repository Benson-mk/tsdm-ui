# TSDM · Simplified

## Overview

Simplified is TSDM's shared interface for forum browsing, reading, discussion and member activities. Its visual frame follows the supplied Figma design: monochrome navigation and primary actions, expressive variable typography, uppercase mono taxonomy, pill controls, generous whitespace, and large pastel panels that read like posters on a clean desk. Color and typography provide most of the depth. Ordinary forum lists and posts use this vocabulary without placing a full-screen introduction before every task.

There are exactly four color themes: **Light, Alias, Mono and Dark**. Light, Alias and Mono are light appearances; Dark is an independent fourth appearance. **All four share the same layout, typography, functionality and responsive behavior.** Mono uses a white canvas with black, white and gray interface colors. Dark uses a black reading frame with white text. A forum thread means a discussion, not a color theme.

The supplied palette values and the four-theme contract remain the baseline. The later request to remove green from Mono overrides its original canvas assignment; Mono now uses only the approved black, white and sampled grays. The latest user decision authorizes other visual rules to move closer to Figma. This edition replaces the earlier sidebar geometry, 700/1000px breakpoints, restricted type scale, 16px card corners and old reading measurements. **Light and 100% text size remain the initial selections.** Text size is the single workspace preference: 70–90% derives Compact spacing, while 100–150% derives Default spacing. There is no independent density selector. The confirmed issue #6 follow-up on 2026-10-18 supersedes the former two post-only reading presets.

This is a standalone English target specification in Google's **DESIGN.md alpha format**, not a claim of a stable Google standard or an already implemented UI. One YAML front matter supplies exportable tokens; the eight canonical sections below supply application rules, responsive overrides and state behavior. All implementation values are here. ### Composition and scope

Use a quiet monochrome frame, a strong opener when the page needs introduction, flat reading content, and occasional full-width colored story panels. An optional forum overview sequence is: plain hero, announcement strip, plain feature summary, pale systems/help panel, inverse community-feature panel, warm event panel, resource grid, footer. Pricing plans, sales funnels and scrolling customer-logo endorsements are not product requirements. ### Text, boundaries and focus

Body text stays black on light surfaces and white on dark surfaces. Use weight and spacing for hierarchy. The limited `muted` role is a forum adaptation for dates and secondary metadata on regular surfaces, never paragraph text or colored panels. On Dark's gray surface use white; if secondary metadata is necessary there, use the existing **#e9e9e9** (4.729:1), never #bebebe (3.089:1). On light soft surfaces black is the baseline. All body links are underlined and use their containing surface's text color.

Normal text must reach 4.5:1; necessary control/state graphics must reach 3:1 against adjacent colors. White on #6d5175 is 6.809:1, on #616379 is 5.884:1, on #666666 is 5.742:1. White on #8c7491 is only 4.182:1, so use black. #666666 on #e3e3e3 is only 4.474:1, so use black there. Black and white have 21:1 contrast.

Decorative separators are 1px **#b8b8b8** on light surfaces and **#666666** on Dark's regular black surfaces. Softer subdivisions use spacing plus those same colors; do not invent the source's unavailable pale grays. A separator alone never identifies a control, selection or focus. Inputs, informative table boundaries and quote rules use **#666666** against white / #eeeeee, **#e9e9e9** against black / #666666, and the panel's own black or white text color on colored backgrounds.

Focus is a two-layer ring chosen by the actual surrounding surface, independently of theme: on white or pastel use a 2px white gap and a 3px black outer ring; on black, dark gray or inverse story colors use a 2px black gap and a 3px white outer ring. Do not clip the ring. When a white action sits inside an inverse panel, keep this same surface-based focus rule. Error, warning and success states use explicit text and distinct icons or borders, without new semantic red, yellow or green.

## Layout

### Frame, spacing and editorial panels

For the selected A workspace, [issue #6](https://github.com/Benson-mk/tsdm-ui/issues/6#issuecomment-6205912078) controls the rail, secondary context, result list, reader/composer and responsive picker/drill-down geometry. The page frame and editorial compositions below describe source layouts; they do not replace that selected workspace. The text-size change retains its pane widths and responsive structure.

Use a sticky top navigation bar and one main workspace. The content box is **max-width 1280px**, centered with **48px outer gutters at width ≥768px** and **24px below 768px**. The 1280px maximum excludes these gutters. Use `min-width: 0` for flexible children. Do not create page-wide horizontal overflow.

The source scale is complete: hair 1px, xxs 4px, xs 8px, sm 12px, md 16px, lg 24px, xl 32px, xxl 48px, section 96px. It is an 8px-centered rhythm with explicit 1/4/12px exceptions. Component-specific padding wins over generic spacing advice: primary 10px 20px, secondary 8px 18px 10px, promo 10px 18px, tabs 8px 18px, inputs 12px 14px, template cards 16px, overview cards 24px.

Signature story panels occupy the full content width, use **48px padding and 24px corners**, and are separated by **96px of page canvas**. A hero/callout variant has **32px corners** with the same padding. Treat a panel as one dominant color composition, typically approaching a viewport in visual presence through content and whitespace. Do not enforce viewport height, clipping or scroll locking. Within desktop poster panels at width ≥960px, an isolated text column occupies up to 50% of the inner width; side-by-side text/media may each occupy half the available width with a 32px gap. Below 960px use full-width stacked text/media. Preserve clear text margins without squeezing long titles or forms.

Below 768px, editorial panels extend to viewport edges, have zero corner radius at those edges, use **24px internal padding**, and have **48px canvas gaps**. Ordinary cards and posts remain inside the page gutters. Ordinary workspace sections use 32px vertical separation (24px below 768px), not the editorial 96px gap. Return to the theme canvas between colored stories: white in Light/Alias/Mono, black in Dark. Several short notices may coexist; the source's one-colored-block-per-viewport rule means one dominant story composition, not hiding adjacent content or enforcing pagination.

### Text size and automatic workspace spacing

Settings presents one **Text size** range slider: **70% through 150%, in 10-percentage-point steps**, initially **100%**, with its current percentage and **Reset to 100%**. Apply and save each input immediately; no OK/Apply step or independent density setting exists. Show the derived spacing mode beside the percentage so the threshold is understandable. Arrow keys move one step; Home/End reach the endpoints without triggering prototype-layout shortcuts.

At 100%, every typography role retains its baseline size, weight, line multiplier and hierarchy. Multiply each role's font size by the chosen percentage exactly once, including navigation, lists, headings, post paragraphs and nested rich text, metadata, code, dialogs and composition. Post body remains the `body` role at weight 320 in both spacing modes: 90% gives 16.2px text at the 16px browser baseline, not a second application of the old 16px Compact role. Line height scales with text; CJK tracking and semantic heading rules remain intact. Decorative icons, images, borders and corner radii do not scale with this control. Text embedded in an image remains part of that image.

The YAML typography and component recipes describe the unscaled baseline. Apply the runtime text multiplier and derived spacing overrides together; do not export the Compact recipe as a second font scale. Use relative typography that composes with the browser's font baseline, and retain normal browser zoom. The slider's 150% endpoint is not an accessibility enlargement ceiling.

Derive **Compact** from a selected value of **70%, 80% or 90%**, and **Default** from **100% through 150%**. The threshold uses the saved percentage, independent of browser zoom and the actual rendered pixel size. Crossing 90% ↔ 100% intentionally changes spacing in one step.

## Elevation & Depth

### Four tiers

| Tier | Use | Exact treatment |
| --- | --- | --- |
| Flat | Hero, colored story, reading surface, ordinary footer | No shadow; separate by surface and whitespace |
| Bounded | Inputs, informative tables, overview/forum cards | 1px boundary; use Colors for decorative versus necessary control contrast |
| Floating | Navigation dropdown, floating menu or an editorial tile intentionally lifted within a composition | `0 4px 16px rgba(0, 0, 0, 0.06)`; never apply to every card |
| Modal | Image/video lightbox and its dialog surface | `0 16px 48px rgba(0, 0, 0, 0.24)` with a `rgba(0, 0, 0, 0.60)` backdrop |

The stronger modal shadow and exact opacity are project resolutions of unspecified/approximate source values. Both effects composite the existing black; they do not authorize translucent component fills. On Dark, do not rely on black shadow to distinguish a floating black surface: also use a 1px #e9e9e9 boundary. Keep normal text fully opaque. Navigation overlays use the opaque canvas, not the lightbox scrim. Modals trap focus, restore it on close and provide a keyboard-accessible close action.

Inverse circular controls use **opaque #666666 with white glyphs** instead of the source's unrepresented 16%-white compositing. This resolves its white-on-white YAML bug and keeps all solid surfaces inside the approved palette. Panel changes remain the primary depth cue; a black announcement strip and inverse story panel are both valid dark surfaces above the footer.

### Illustration and motion

Decorative sticky-note thumbnails may alternate static **-2° / +2°** rotations; keep those angles at every breakpoint. These numeric angles are project choices, not sampled source measurements. Rotate only decorative wrappers, never reading text, controls or user attachments. Embedded UI mocks stay flat; any illustrative floating layer uses the single floating-tier shadow rather than an invented shadow system.

UI hover/focus transitions use **160ms ease-out**. Primary press scales only the inner visual to **0.98**, with the hit area and layout unchanged. Optional resource-thumbnail reveal runs once for **160ms ease-out**, from opacity 0 and translateY(4px) to opacity 1 and translateY(0); content remains present without scripting. Lazy-load offscreen resource thumbnails and reserve their dimensions; do not lazy-load a primary above-fold image. Announcements are static, not an autoplay logo marquee. Under reduced motion, omit reveal, press scaling, rotation transitions and all nonessential animation; static decorative angles may remain. Loading must remain understandable without movement.

| Navigation | `top-nav`: opaque regular surface, body-sm, 56px baseline, brand / destinations / secondary and primary actions. Hamburger overlay, wrapping and keyboard behavior follow Layout. |
| Announcement strip | `announcement-strip`: black with white body-sm, 36px single-line baseline below navigation. Static concise forum notice; content-driven height when wrapping. If actionable, enlarge the entire strip to ≥44px. |
| Footer | `footer`: regular surface, **96px vertical / 32px horizontal padding**, no shadow. Display-lg wordmark at leading edge, short mono caption column headings and body-sm links. Use four equal columns ≥960px, two at 560–959px and one below 560px; use 48px vertical / 24px horizontal padding below 768px. It is not an inverse black footer in the light themes. |

Use at most one primary **per action group**; avoid duplicating the same action in a hero and visible toolbar. Persistent navigation may contain a distinct global action while a contextual workspace has its own action. This explicitly resolves the source's conflict between navigation-plus-hero primaries and a blanket one-per-viewport rule. Filters may show one selected pill independently of an action group.

### Forum patterns and rich content

Forum directory cards use `forum-card`, 24px padding/corners, card-title headings and concise descriptions. They can use a resource grid when appropriate; thread lists are one-column rows, not four-column cards. Thread, search, favorite and notification rows use `thread-row`; title, metadata and moderation/availability indicators remain visible. Rows grow with content. Hover underlines the title. Use an actual link for navigation and separate buttons for operations; never nest interactive controls inside a card-wide link.

Posts separate identity and metadata, body, and contextual actions. Use the automatically derived `reader-post` recipe; a targeted post has a 2px current-ink outline on its regular surface and retains the focus gap where needed. Quotes use the soft surface, 16px inset and a 3px control-boundary left rule. On mobile, nested quotes stop increasing indentation after two levels while preserving boundaries and hierarchy. Code preserves whitespace and scrolls within its own region. Tables keep headers, 1px informative boundaries and 8px 12px cell padding; wide tables scroll independently. Ordinary post tables remain data tables on narrow screens; only product-style comparison matrices become per-item accordions below 960px.

Body links always underline and inherit the selected reading role. Use `body-link` on a regular surface, `body-link-on-soft` on quotes/code, black on pastel and white on inverse panels. Lists retain bullets or numbering. Images keep their original colors and dimensions within the available width. Expandable spoilers expose labeled open/closed state and keyboard controls. Attachments and unsupported embeds provide a clear description and an honest native entry when Simplified cannot render them. Permission notices remain distinct from readable content.

### System states

Use `notice` for explanatory status with a heading/icon and black text. Its color does not encode severity. Field errors use `text-input-error`; dialogs use `lightbox` only where a modal interaction is appropriate.

| State | Meaning and available action |
| --- | --- |
| Loading | Explicit progress text; keep relevant navigation and cancel if supported; do not present stale content as current |
| Empty | State that the current board/filter really has no matching content; retain navigation and filter recovery |
| Permission / login | Distinguish insufficient permission from unauthenticated state; offer the supported account flow or native verification entry |
| Missing | Explain missing/deleted content or an invalid link |
| Challenge | Explain the required native site verification; retain the exact recovery destination |
| Unknown / presentation failure | Explain that content cannot be displayed reliably and offer native recovery |
| Session change | Identify the changed account state and stop presenting previous-session content |
| Redirect | Preserve the actual destination; use native continuation when the destination is outside supported Simplified scope |
| Suspended | Label paused browsing distinctly from active loading |
| Error | Brief reason, preserved input and an available retry or native recovery; no invented success |
| Success | State the completed effect, such as saved/submitted, and reflect the confirmed server result |

### Preferences and persistence

Theme selection presents Light, Alias, Mono and Dark as named choices with swatches and an explicit selection indicator. Text size presents the slider, current percentage, derived spacing mode and reset described above. Store explicit preferences; if storage is unavailable retain them for the session and disclose that the size will not survive reload. First use is Light + 100% text size (Default spacing). Restore a valid saved text size before the workspace is shown; invalid or out-of-range values fall back to 100%. Reset also saves 100%. Apply the full selected palette before showing the workspace to avoid a white flash. Scope native controls' `color-scheme` to Simplified (`light` for the first three, `dark` for Dark). System preference does not override a saved choice; there is no automatic system-following mode in this specification.

Theme, text-size and language changes preserve workflow/editor identity and state as specified in Layout. Their behavior is identical in all themes. Use native buttons, labels, links and appropriate selected/current/expanded/disabled semantics; all operations remain keyboard reachable. Modal, navigation and floating-menu focus must remain visible on their actual surface.

## Do's and Don'ts

- **Do:** Start with the monochrome frame, choose a single dominant section surface, then use body, subhead and headline according to content hierarchy. Reserve oversized display for editorial openers.
- **Do:** Use the named fine weights, size-dependent Latin tracking, uppercase mono taxonomy, pill actions, circular icons and full-width colored panels with generous canvas between them.
- **Do:** Keep all four themes geometrically identical. Keep Mono's interface neutral and supply complete foreground/background pairings in Dark.
- **Do:** Pair primary and secondary actions when both serve the current task. Distinguish selection, focus, disabled, pending and failure states through semantics and visible non-color cues.
- **Do:** Preserve complete titles, post content, real links, editor state, image colors and honest native recovery.
- **Don't:** Add undocumented accent colors, gray paragraph text, opacity-based text hierarchy, shadows to every section, square action controls or mono paragraphs.
- **Don't:** Interpret one dominant colored story as permission to hide neighboring content, force viewport-height panels or prevent ordinary scrolling.
- **Don't:** Turn theme or text-size selection into a feature switch, crop UI previews, shrink mobile targets, autoplay a customer-logo marquee, or mistake permission/error states for an empty list.

### Iteration guide

1. Choose one named component or coherent family and its purpose. Select an existing surface before adjusting typography or layout.
2. Keep all four themes in sync. Define complete named state entries; for shared behavioral states, state the geometry-preserving rule explicitly. Any new palette role must use an existing approved value and a verified foreground.
3. Apply the responsive ranges, CJK tracking override, text-size range and automatic spacing threshold and surface-based focus treatment. Check regular, pastel, soft and inverse surfaces, not only the default page.
4. Run the official `designmd lint DESIGN.md`; inspect contrast, broken references and orphan warnings. Export `json-tailwind` and `dtcg` and inspect token completeness, especially line heights. The pinned verification baseline is `@google/design.md@0.4.0`.
5. For an implementation, exercise 375, 559, 560, 767, 768, 959, 960, 1280, 1400, 1440 and 1920px widths, keyboard navigation, user zoom, touch targets, long CJK/Latin titles, posts, forms, tables, images, reduced motion and 70%, 90%, 100% and 150% text size in every theme. The document validator does not test browser behavior.
6. Recheck action priority: one primary per group, no redundant hero/toolbar action, at most one promotional action per page. Record any deliberate source departure and remove superseded rules instead of appending competing instructions.
